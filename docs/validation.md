## Причина и исправление closest_columns

До исправления минимальный вызов из linalg.ic.sql_in приводил к signal 11 PostgreSQL. Отладка на отдельной копии кластера показала стек освобождения строки: `dist_fn_name → std::__cxx11::basic_string → operator delete → pfree`. MADlib подменяет локальные C++ new/delete на PostgreSQL palloc/pfree; строка, созданная внутри libstdc++ stream, пересекала несовместимые границы распределения памяти.

В `deploy/bench/patch_madlib.py`:

- dist_fn_name больше не использует istringstream/getline и динамическую std::string; имя функции выделяется указателем, сравнивается strcmp;
- сборка сохраняет C++11, но использует legacy libstdc++ string ABI (`_GLIBCXX_USE_CXX11_ABI=0`); это устраняет аналогичный сбой PMML, проявившийся после локального исправления closest_columns;
- проверки поддержки языка в MADlib отделены от выбора string ABI; добавлены явные стандартные заголовки для GCC 12;
- исправлено отдельное переполнение стека в FunctionHandle для PostgreSQL 12+: FunctionCallInfoBaseData содержит гибкий массив аргументов, поэтому выделяется LOCAL_FCINFO с FUNC_MAX_ARGS вместо одного базового struct.

Патчи применяются к исходникам MADlib 2.1.0 при сборке. Ключевые замены проверяют ожидаемый исходный текст и прерывают сборку при несовпадении. Это локальный compatibility patch, не новая upstream-версия MADlib. Проверка closest_columns находится в `deploy/bench/closest_columns.sql`, запускается при первой инициализации и доступна для повторного запуска в `/opt/checks/closest_columns.sql`. Она транзакционная, объекты откатываются.

Полный install-check успешно прошёл 60 штатных проверок, включая linalg, PMML и regress. Это результат набора install-check установленной версии; он не означает поддержку всех алгоритмов через API приложения.

## Проверки реализации

`tests/integration/test_control_plane.py` выполняется против настоящих metadata и bench PostgreSQL. Для каждого теста создаются отдельная управляющая схема и уникальные bench-объекты. Сценарий с версиями меняет исходную таблицу после snapshot, создаёт вторую версию, затем успешно обучает модели на первой: изменённые исходные значения не попадают в старую версию.

Матрица проверяет общий подготовленный набор для каждой пары, качество предсказаний, исключение warmup из количества измерений и доступность JSON. Другие проверки покрывают очереди, конкурирующий захват, fencing, просроченную аренду, timeout, отмену и миграции. Дополнительно проверены отклонение NULL и согласованность адаптеров без intercept.

Локальные журналы: `artifacts/madlib-fixed-install-check.log`, `artifacts/benchmark-tests.log`, `artifacts/bench-fix-build.log`. artifacts исключён из Git. Старый `madlib-install-check.log` оставлен как запись исходного сбоя.

Дополнительный HTTP-прогон на Compose-сервисах: experiment `598f8a3a-a821-4c22-99c9-f20d5a906278`, два размера 50/100, по одному прогреву и два измеряемых повтора на backend. Все 12 runs завершились успешно; RMSE обоих адаптеров ниже 1e-7. Скачанный JSON проверен по SHA-256 из metadata. Локальные файлы `artifacts/http-demo-results.json` и `artifacts/http-demo-artifact.json` сохраняют результат проверки. API и worker оставлены работающими, обе БД healthy, миграция завершилась с exit code 0.

## Границы результата

Поддерживается линейная регрессия на плотных числовых данных без пропусков. Неизменяемость версий действует на уровне API, не ограничивает администратора БД. Предварительная оценка памяти sklearn не является жёстким лимитом процесса; Compose ограничивает контейнер.

Реализованы фазовые wall-clock таймеры, CPU/RAM sampler для executor и bench-контейнера, парные bootstrap-интервалы и рекомендации по cases. Ещё нет автоматического retry, retention/уборки оставшихся объектов, внешней авторизации и разделения ролей БД. Методика и ограничения описаны в [измерениях и рекомендациях](measurement-and-recommendations.md); синтетическая проверка не доказывает универсальное преимущество одного подхода.

Воспроизводимые Dockerfile сохранены, обход внешнего реестра использовался только в локальных artifacts/Dockerfile.*-local. Обновлённый bench-образ собран штатно.
