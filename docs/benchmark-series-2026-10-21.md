# Сравнение на шести наборах данных — 21 октября 2026

Серия `20261021_a`: 6 источников и 6 неизменяемых версий, 6 экспериментов, 132 успешных запуска. В статистику вошли 60 измеряемых пар; 12 прогревочных запусков исключены. Ошибок попыток и исключённых измеряемых пар нет.

## Данные и условия

Линейная регрессия с intercept. Размеры: 1 000, 10 000 и 100 000 строк; 5 и 20 числовых признаков. Генератор `deploy/bench/generate_series.py` использует NumPy PCG64, seed 20261021, независимые стандартные нормальные признаки, intercept 3 и нормальный шум σ=0,1. Коэффициент признака с индексом j от нуля: `(-1)^j * (j+1)/p`. Меньшие наборы — префиксы соответствующего большого набора; пропусков нет.

На каждый набор: общее разбиение 80/20 с seed 42, одна прогревочная и десять измеряемых пар, один поток Python BLAS. Порог RMSE 0,15, минимум десять пар, практически значимое преимущество 5%. Ресурсные бюджеты не заданы. Worker исполнял задания последовательно; генерация данных завершилась до начала измерений. Compose: worker 2 CPU / 1 GiB, PostgreSQL 2 CPU / 2 GiB. Стек: PostgreSQL 15.19, MADlib 2.1.0 с локальными compatibility patches, Python 3.12.15, scikit-learn 1.9.1, NumPy 2.5.4.

Время — медиана `model_wall`, включающего подготовку адаптера, обучение, предсказания и запись результатов. Общая подготовка выборки, очередь, запуск процесса и расчёт качества сюда не входят. Отношение — медиана **парных отношений**, поэтому может отличаться от отношения двух медиан времени.

На этих данных scikit-learn выигрывает при 1 000 и 10 000 строках, MADlib — при 100 000. Точная точка смены преимущества не установлена: промежуточные размеры не проверялись.

Для 100 000 × 20 медиана подготовки sklearn составляет 0,931 с, обучения — 0,034 с; у MADlib соответственно 0,007 и 0,213 с. Таким образом, выигрыш MADlib относится к полному измеряемому циклу, включая передачу данных и запись предсказаний. Это не утверждение о более быстром собственно обучении MADlib.

## Повторение

Из корня репозитория, при запущенных сервисах и отсутствии других измеряемых задач. Для новой серии используйте новое имя: генератор не перезаписывает существующие таблицы. Зависимости frontend устанавливаются через `yarn install --frozen-lockfile`; драйвер по умолчанию использует установленный Microsoft Edge.

```powershell
New-Item -ItemType Directory -Force artifacts | Out-Null
Get-Content deploy/bench/generate_series.py -Raw | docker compose exec -T worker python - --series next_series > artifacts/series-next.json
node frontend/scripts/run-series.mjs artifacts/series-next.json
docker compose cp artifacts/series-next-state.json worker:/tmp/series-state.json
Get-Content deploy/bench/verify_series.py -Raw | docker compose exec -T worker python - /tmp/series-state.json > artifacts/series-next-audit.json
```

Повторный запуск UI-драйвера с тем же manifest использует checkpoint и проверяет существующие эксперименты. Для пересчёта моделей создавайте новую серию. Адрес UI переопределяется через `FRONTEND_URL`, браузер — `PLAYWRIGHT_CHANNEL`.

Синтетические плотные данные, один split и одно окружение ограничивают область вывода. Политика кеширования — uncontrolled warm cache. Интервалы рассчитаны отдельно по каждому варианту без поправки на множественные сравнения; повторы измеряют вариацию времени, а не неопределённость качества на новых данных. Методика подробно описана в [измерениях и рекомендациях](measurement-and-recommendations.md).
