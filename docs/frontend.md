# Frontend: Vue и Yarn

Интерфейс реализован на Vue 3 (Composition API), TypeScript, Vue Router и Vite. Пакетный менеджер — Yarn Classic 1.22.22; точные зависимости закреплены в frontend/yarn.lock. Для разработки используется Node 24. Шрифты Golos Text поставляются локально с приложением; обращения к внешним сервисам для отображения UI не нужны.

## Запуск через Docker

Из корня репозитория:

```powershell
docker compose --profile bench up -d --build bench-db
docker compose up -d --build api worker frontend
```

Откройте http://localhost:8080. Для существующей bench-БД должна быть установлена функция мониторинга по [инструкции](measurement-and-recommendations.md). Данные уже работающего стенда сохраняются.

Frontend собирается Yarn в многоэтапном Dockerfile, Nginx раздаёт статику и проксирует /api и /health на FastAPI. API и frontend имеют один origin; отдельная настройка CORS не нужна. Прямые переходы и обновления вложенных маршрутов поддержаны через SPA fallback. Локальные порты привязаны к 127.0.0.1.

## Разработка

Сначала запустите backend через Compose, затем:

```powershell
cd frontend
yarn install --frozen-lockfile
yarn dev
```

Dev-интерфейс: http://127.0.0.1:5173. Vite проксирует запросы к API на http://127.0.0.1:8000. Для другого адреса задайте API_PROXY_TARGET до yarn dev. Сборка: `yarn build`; форматирование: `yarn format`. `yarn preview` предназначен для просмотра собранной статики; API-прокси настроен именно для dev-сервера, полный production-сценарий проверяйте через Compose/Nginx.

## Пользовательский сценарий

1. В «Датасетах» зарегистрировать существующую таблицу bench PostgreSQL, указав ID, числовые признаки и целевой столбец. Загрузка CSV пока не реализована.
2. Нажать «Создать версию». Дождаться готовности snapshot; ошибка отображается в строке версии.
3. Выбрать «Создать эксперимент» у готовой версии или открыть форму из списка экспериментов.
4. Указать размеры выборок, intercept, повторы, прогревы, test-долю, seed и критерии. «Проверить конфигурацию» вызывает реальную API-валидацию и показывает матрицу.
5. Сохранить эксперимент. Это создаёт draft; обучение ещё не запускается. В карточке нажать «Запустить».
6. Наблюдать за статусами и прогрессом. Отмена требует отдельного подтверждения в интерфейсе.
7. Выбрать вариант сравнения в результатах, изучить время, CPU/RAM по двум областям, RMSE и рекомендацию с интервалом. Скачать JSON-отчёт; отдельные артефакты находятся во вкладке попыток.

Данные в UI поступают из API, демонстрационные значения не подставляются. График времени использует медианы полных измеряемых пар. Качество в таблице — медианы успешных измеряемых запусков. Прогревы не входят в статистику. Отсутствующие ресурсы обозначены «—» и количеством доступных измерений, ноль остаётся нулём.

История имеет страницы по 30 записей, поиск и фильтры применяются к текущей странице; счётчики явно относятся к ней. Источники и версии загружаются с пагинацией API. Обновление статусов — каждые четыре секунды, проверка доступности API — каждые десять. Есть обработка ошибок сети, тайм-аутов и ответов 422/503, повтор загрузки, состояния пустых списков и мобильная навигация. Параметры сохранённого эксперимента доступны во вкладке конфигурации.

## Добавленные API

- GET /api/v1/experiments — история, limit до 100 и offset.
- GET /api/v1/datasets — зарегистрированные источники, limit/offset.
- GET /api/v1/datasets/{id}/versions — версии источника, limit/offset.

Сортировка — created_at DESC, id DESC; миграция схемы не требуется.

## Проверки

```powershell
cd frontend
yarn build
yarn format:check
yarn test
```

В Windows тесты используют установленный Microsoft Edge. На другой платформе можно установить Chromium командой `yarn playwright install chromium`, задать PLAYWRIGHT_CHANNEL=chromium и выполнить yarn test. Тесты поднимают Vite автоматически или используют уже запущенный сервер на 5173.

Семь Playwright-сценариев проверяют историю и фильтры, валидацию/создание/явный запуск, регистрацию/версию датасета, сетевую ошибку и повтор, мобильную навигацию, отсутствующие ресурсы, подтверждение отмены. API в них подменён тестовыми ответами: реальные обучающие задачи не запускаются.

Дополнительно проверены два интеграционных API-теста на metadata PostgreSQL: новые списки/пагинация и совместимость миграций. Реальные страницы истории и результатов просмотрены в Edge через production Nginx на desktop и mobile; ошибок JavaScript и горизонтального переполнения страницы нет. Существующая история используется только для чтения. Нагрузочные серии оставлены на следующий этап по решению пользователя.
